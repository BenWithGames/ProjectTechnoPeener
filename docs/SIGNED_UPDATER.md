# Signed automatic updates

The updater is isolated from combat: StatusOverlay's worker thread launches a hidden, below-normal-priority Windows PowerShell 5.1 helper. There are no HTTP calls or update waits on the game update thread. The overlay displays the compiled build and a mouse-accessible Check for updates button. Checks run on startup and every 15 minutes; manual checks are limited to one per 30 seconds. Creating `Mods/SC6Rollback/updates.disabled` opts out. Nothing uploads reports or personal data. Requests disclose the normal client network address and a generic updater user agent to the hosting services.

The compact update button has a visible border, hover highlight and pressed state. While checking, it shows a rotating ring and “Checking...”. Once the signed manifest identifies a newer build, it shows “Update available” in red during download and while waiting for game exit. The status underneath distinguishes download progress from readiness to install. Checking animation refreshes only the overlay thread; combat does not wait for it.

Hosting:
- Manifest: https://benwithgames.github.io/sc6astral-updates/update.json
- Download origin: https://sc6astral-downloads.ben-tmarkham.workers.dev/
- Manual releases: https://github.com/BenWithGames/sc6astral-updates/releases

The JSON envelope contains schema=1, a base64 UTF-8 payload, and a base64 RSA-3072/SHA256 PKCS#1 v1.5 signature over the exact payload bytes. The helper pins the public RSA key. The payload contains schema, a monotonically increasing 14-digit build, issue/expiry Unix timestamps, exact download URL, size and SHA256. A manifest expires in 90 days. Re-sign before expiry; edits invalidate its signature. Older builds, invalid signatures, expired manifests, HTTP, redirects, other origins, extra URL parameters and packages over 64 MiB are rejected. Network failure never interrupts gameplay. The request timeout is 15 seconds, reads are bounded, and checks never loop rapidly when the free download route is unavailable.

Automatic ZIPs are distinct from manual installation ZIPs: exactly five flat files (`main.dll`, `SC6Astral-Updater.ps1`, `Archive-AutomaticReport.ps1`, `connection.mp3`, `UpdateVersion.json`). No downloaded installer script is executed. ZIP entries are allowlisted, unique, non-link, and total expanded size is bounded. The original installed helper performs installation. Game and UE4SS runtime hashes must match the signed package's prerequisites. Updates never change UE4SS settings, mods.txt, automatic-play.enabled, logs, or user settings. Bootstrap changes require a separate full installer.

The helper holds a handle to the launching game process and waits for its exit, then checks that no SC6 process is running. It verifies the signed manifest and ZIP again after the wait, re-extracts fresh files, creates backups and a transaction journal, and atomically replaces individual files. The DLL and version record are last. An error restores old files; an incomplete transaction is recovered after the next SC6 exit before attempting another update. The updater never kills/restarts the game and never silently elevates. Do not relaunch SC6 until update installation finishes. A locked/permission-protected install fails safely; use the manual installer if required. This is not an atomic filesystem transaction across all files: backup recovery covers interruption between replacements.

Staging directories/downloads are discarded after each attempt and stale staging is cleared on startup, with constrained nonrecursive cleanup. Backups are retained for recovery under `updates/backup-*`; they are separate from the ten-report retention policy for match logs. Status is in `updates/status.txt`, latest error in `updates/last-error.txt`; neither is uploaded.

Publishing:
1. `Initialize-UpdateSigning.ps1` creates the RSA key once, encrypted with Windows DPAPI CurrentUser at `%LOCALAPPDATA%/SC6AstralPublisher/signing-key.dpapi`, outside the repository/packages. Re-running does not rotate it. Back it up securely; moving it to another Windows account requires a deliberate secure key migration. Losing it prevents future signed updates for existing installs.
2. `Build-Native.ps1` runs tests, generates UpdateBuild.hpp and stages matching UpdateVersion.json after successful DLL compilation.
3. `Package-AutomaticPlay.ps1` produces the first-install/friend package (including the updater). `-UpdateOnly` is the existing manual updater format, not the automatic format.
4. `Publish-UpdateFiles.ps1` produces a dedicated automatic ZIP and signed update.json in Downloads/SC6Astral-Publish-<build>. Upload the ZIP to private R2, verify the Worker download hash, then commit update.json to the distribution repository's main root LAST. Do not upload signing keys or test fixtures. The mod cannot update until both hosted files exist.
5. Workers must remain on Free, with R2 public access disabled. The Worker quota is a request cutoff, not an account-wide budget cap. GitHub Pages supplies version checks; no GitHub REST API is used.

Validation: Test-SignedUpdater.ps1 covers signature tampering, wrong keys, URL restrictions, expiry, downgrade rejection, archive size/hash/entry boundaries, build mismatch, runtime mismatch, live-game rejection, preservation and transactional recovery. Test-UpdaterLifecycle.ps1 uses a synthetic named game process and a separate Windows PowerShell helper with fixture transport: it proves staging during the process lifetime and installation after exit. It never contacts the publishing services or terminates a real game. Live overlay mouse interaction and real hosted update delivery still require a game test after publishing.
